# 终点三白光 RGB 全图参照块 Huber 校正先导测试方案

**执行版本 1.0 · 2026-11-26 · 项目 teeth_student**  
**交付终点**为三个指定牙号与视角的真实图像测试、原分辨率对照图和可复算报告。方法是在整张白光图内寻找本色稳定、身份可辨认的小块，用其估计当前图到同牙同视角 S0 的三个颜色通道映射。牙根不参与新方法的取样和配准。

## 给本地 Codex 的执行指令

> 在项目根目录按本文件完成先导开发，并在真实原始白光图上执行到第 7 节验收。只实现“成对稳定参照块＋逐通道带截距 Huber”这一种方法。先冻结样本、参照块和参数，再生成校正图。对不能确认的材料、做不了的拟合、无法评价的指标，按规定逐帧留痕并继续其他帧。交付运行目录、实际分母、失败原因、对照图和复现命令。三牙先导即为本次终点。九牙全量、分类训练、重算 QLF、切换校色算法属于另行立项的工作。

## 2．在原图上选取真实参照块

**参照块靠实物身份配对。** 当前图与 S0 图可以有平移、旋转和不同构图。在两张图中分别找到同一块表面，分别画出它的内部区域即可。无需全牙逐像素对齐。新方法的计算资格独立于 v1.1 牙根配准结果。

| 可以取样的区域 | 需要保存的依据 |
|---|---|
| 同一夹具、标尺、色卡或固定衬片上可重复辨认、表面哑光、与牙冠受光相近的不同色块 | 用刻线、边界、固定标记或装置记录说明两图中为何是同一材料、同一块。尤其核实 C04 的 S2 是否沿用相同材料。色块本身可以有颜色。 |
| 实验记录明确始终未处理、且不属于牙根的固定区域 | 记录保护范围、位置标志及依据。处理范围不明确的牙面留给观察。 |

在原图上避开处理牙冠、牙根、高光、深阴影、遮挡、标签文字、软件补边和接近饱和的纯黑纯白区域。同一片均匀材料切成许多小格，只计一个实物块。优先找反射明暗本来就不同的表面，不能用同一表面上会随拍摄移动的阴影制造亮度跨度。

**先导允许人工辅助定位。** 本地 Codex 先用已有查看、标注工具或可审阅的局部定位结果，完成原图核对并保存标注。每个 `patch_id` 对应物理身份，每个 `image_id` 的多边形用该张白光原分辨率、EXIF 正向后的坐标。保存参照块名称、身份依据、两图叠框截图、可见性和定位方式。连拍间复用框时要核对该帧实际位置。报告人工辅助和自动定位数量，避免把人工可行性误写成自动识别率。

先保存全部候选块和剔除理由，再看新校正效果。选点依据是材质和几何对应，禁止按“与 S0 的颜色已经很接近”、拟合残差、校正后色差或阶段分数挑块。看得清原图却找不到可信参照，记为 `no_confirmed_patch`。原图读不到或缺少核实身份所需资料，另记 `input_missing` 或 `identity_unverified`，与已检查的照片分开报告。

## 3．冻结取样和留出规则

以下数字是本先导预先指定的工程参数。程序保存每块有效像素数和每通道实际跨度，便于判断哪些帧接近门槛。本轮不根据出图数量调整这些值。

1. 使用 v1.1 相同的原始白光解码、方向及色彩管理逻辑。对每个块，分别在当前图和参考图冻结有效像素。编码 sRGB 8 位下任一通道 ≤5 或 ≥250 的像素剔除，同时剔除上节标注的反光或遮挡。每一侧至少留下 **25 个像素**才形成一个区域中位数。两侧无需有相同数量或位置的像素。
2. 在 **0–1 线性 sRGB** 中分别取该块 R、G、B 的中位数。同一帧与参考帧中同名、两侧都有效的物理块形成一对。每对权重为一。拟合至少要有 **2 个不同物理块**。在当前和 S0 两侧，对各通道的块中位数都计算 P90−P10，分位数采用线性插值，六个跨度均须 **≥0.02**。这样可以识别“看似有很多点，实际只有一个亮度”的情况。
3. 若有至少 3 个有效块，按预先分配的 `patch_id` 字典序试留一个完整的物理块。选择第一个使剩余拟合块仍满足上条数量与跨度的块。若没有可留出的块，但全部块合用满足拟合条件，继续出图，记为“无独立留出”。只有 2 个拟合块时，另记 `two_point_support`，即便有输出也单列。两点能确定直线，对异常块的抵抗能力无法靠这两点验证。
4. 将每帧的拟合块、留出块、有效像素掩膜和参数写入冻结清单，保存哈希。同一帧的原图、旧方法和新方法只在计算评价指标时使用留出块。这里的独立性限于该帧求系数的过程。

只有一个亮度、跨度不足或没有可信实物对应时，登记原因，本帧校正图路径留空。单灰块增益法、灰世界、直方图匹配、Retinex、返回牙根拟合及用原图冒充校正图均不在本协议内。

## 4．每张图如何拟合和输出

对非参考帧的每个通道 `c`，令 `x(j,c)` 为当前原图第 `j` 块的线性中位值，`y(j,c)` 为 S0 同一块的线性中位值。都使用相同的拟合块集合。

$$
y_{j,c}\ \approx\ a_c x_{j,c}+b_c,\qquad c\in\{R,G,B\}.
$$

逐通道用带截距 Huber 回归直接拟合 **当前 → 对应 S0**，每帧独立得到六个系数。复用 v1.1 实际使用的 Huber 数值内核、损失参数和收敛标准，在运行前把函数位置、参数及软件版本写入冻结配置。旧函数若将牙根取样与求解封装在一起，只在新实验脚本中适配配对值到同一数值内核。牙根密集小块数量门槛由第 3 节的实物块规则取代。真实阶段、牙冠统计量、QLF 四项和其他帧均不参与求解。

各通道须收敛，系数有限且斜率为正。把 `a_c × 当前通道 + b_c` 应用到原图每个像素，先在浮点空间记录小于 0 或大于 1 的位置，再裁切到 [0,1]，转回编码 sRGB，仅量化一次，保存原取景、原分辨率的 RGB PNG。技术合格但色差变大或牙冠出现裁切的帧仍须保留。

每帧给出一个主状态和具体原因。

| 主状态 | 含义 |
|---|---|
| `reference` | S0 专用参考，三个倍率为 1、截距为 0。只提供参照。 |
| `ok_evaluable` | 成功输出 PNG，并有独立留出块。 |
| `ok_no_holdout` | 成功输出 PNG，因无独立留出块，色差栏记缺失。 |
| `unavailable` | 原图可检查，但缺可信参照、共同有效块不足、跨度不足、求解未收敛或系数无效。记触发项及实测值。 |
| `input_error` | 数据或身份依据缺失、样本键冲突、文件解码失败等。记录可修复的具体依赖。 |

`two_point_support` 为附加标记。已有可靠的当前图牙冠掩膜只用于评价。缺此掩膜时，牙冠指标记缺失，拟合和出图继续。

## 5．怎样判断有没有帮助

| 观察量 | 固定比较口径 |
|---|---|
| **S1、S2 是否多覆盖了图像** | 在完全相同的非参考帧上，S0、S1、S2 分别报告新旧成功数／应测数。新法成功为两个 `ok` 状态之和。另列“至少 3 个拟合块且有独立留出”的数目。逐阶段列出旧失败→新成功、旧成功→新失败、两者都成功、两者都失败四格及未知旧状态。保留空组和只有零星可用帧的原采集组。 |
| **稳定材料的颜色是否更接近 S0** | 在新法的独立留出块，用冻结的原始有效像素分别读原始白光、实际输出 PNG 和 S0。取编码 sRGB 的逐通道块中位数，转到 CIELAB，固定 D65、2°，计算 CIEDE2000（ΔE₀₀，三个权重均为 1）。逐帧记录 `D原−D新`，正数为改善，另报明度误差 `abs(ΔL*)` 和色度平面距离 `sqrt((Δa*)²+(Δb*)²)`。旧 PNG 可用时，在**同一帧、同一留出块**重算 `D旧−D新`。v1.1 报告中牙根留出的 6.31、1.55 不能直接拿来作本试验的色块基准。 |
| **牙冠是否付出了代价** | 使用相同原图和同一当前帧有效牙冠掩膜。新增裁切率为“原本三通道均在开区间 (0,1)，变换后任一通道越界的有效牙冠像素数／有效牙冠像素总数 × 100%”。用 v1.1 保存的系数在原图上复算旧值，用新系数算新值，计数均在裁切和量化之前。对共同可评集分别给出新旧裁切率的中位数、P90 和最严重帧，另报逐帧 `C旧−C新` 的中位数（百分点，正数为裁切减少）。对新救回的帧单列新法裁切分布。 |
| **I0654 的棕黑纹是否保留** | 从该 ID 的原始白光预先固定棕黑纹局部框，保存像素坐标。在一致显示尺度下并排放原始、旧、新、裁切位置。报告有效牙冠像素、新旧越界像素、百分比和配对差。先核对旧值按两位小数是否为 53.73%。若口径或掩膜不符，写明差异。若新法无法处理该帧，展示原图、旧图和具体原因。缺新图时，本例结论为无法比较。 |

每个差值都先在同帧内计算。色差增益再按原采集事件取帧中位数，每牙取事件中位数，若给总体数字则对可评牙等权平均，并写明实际牙数及各阶段分母。帧级改善、变差、持平的数目一并保留。分母为零时显示 `NA`。三个组合是针对既有问题挑的先导案例，不估算九牙总体成功率，也不做分类性能推断。

**报告须逐项给出结论。** 说明 S1、S2 各自救回多少帧、同时丢了多少旧成功帧，量化留出材料上的色差改善，并说明牙冠裁切和 I0654 的外观如何变化。方向冲突就逐项报告。缺独立参照或对照不齐时标“证据不足”。工程验收以方法、可复算性和覆盖记录为准，效果的正负均是有效研究结果。

## 6．实现入口与交付

在 `stage3/experiments/rgb_patch_huber_pilot.py` 新增隔离的实验入口，按需调用已有库函数。所有新运行写入独立的 `runs/rgb_patch_huber_pilot_<时间>/`。以下是本地 Codex 需要实现的接口，路径相对于 `stage3`。

```powershell
# 在已解压的 stage3 源码根目录执行
$trialDir = Join-Path 'runs' ('rgb_patch_huber_pilot_' + (Get-Date -Format yyyyMMdd_HHmmss_ffffff))
$pyExe = '.\.venv\Scripts\python.exe'
$entry = '.\experiments\rgb_patch_huber_pilot.py'
& $pyExe -B -X utf8 $entry prepare --data 'data/study' --study-run 'runs/study' --baseline 'runs/rgb_root_huber_full_20261126' --out $trialDir
# 本地执行者按第 2 节核对原图，在 $trialDir 下填完 regions.jsonl
& $pyExe -B -X utf8 $entry freeze --prepared $trialDir --regions (Join-Path $trialDir 'regions.jsonl')
& $pyExe -B -X utf8 $entry run --prepared $trialDir --out (Join-Path $trialDir 'run_a')
& $pyExe -B -X utf8 $entry run --prepared $trialDir --out (Join-Path $trialDir 'run_b')
& $pyExe -B -X utf8 $entry verify --prepared $trialDir --first (Join-Path $trialDir 'run_a') --second (Join-Path $trialDir 'run_b')
```

| 最少交付 | 必须能够查到的内容 |
|---|---|
| `pilot_manifest.csv`、`regions.jsonl`、`protocol-lock.json` | 按帧记录来源、参考与分组。按块记录每侧物理身份、多边形、掩膜、可见性和依据，同时保存各帧块角色及哈希、参数和软件版本。冻结清单可引用同目录掩膜文件。 |
| `patch_measurements.csv`、`frame_results.csv`、`corrected_rgb/` | 逐块记录配对中位数、有效像素数及角色。每个输入 ID 恰好一行状态、原因、六系数、块数、跨度、色差、裁切分子分母、旧状态和实际输出路径。 |
| `report.md`、`figures/` | 用实际数字回答第 5 节。至少展示两图同一物理块的叠框、一次真实失败或无参照的原因示例（如有）、分阶段覆盖对照、I0654 原尺度对照。可视化缺失位置用文字标明。 |
| `verification.json` | 数值用例、只读输入哈希核对、逐行对账、两次输出像素和数值比较、真实复现命令。 |

`prepare` 负责发现来源、建立全样本清单和标注工作表。`freeze` 在标注完成后依第 3 节生成有效掩膜和每帧角色，封存源图、区域、配置及清单的哈希。`run` 核对哈希并只读冻结输入。`verify` 生成 `verification.json`，并将数值核验及回放结论列入报告。复跑已有冻结试验可直接从 `run` 开始。使用现有查看工具和一份可审阅坐标文件即可，先导无需开发新的标注平台。若真实图片可查看，交付应包含对实际参照是否存在的检查，只有空白模板不能算测试完成。

## 7．交付前核验

1. **线性方向及三通道。** 用四个合成拟合块，三个通道的当前值均依次取 0.20、0.40、0.60、0.80。构造参考值 `R'=1.10R+0.01`、`G'=0.90G+0.02`、`B'=1.05B−0.01`。独立输入 (0.50, 0.50, 0.50) 应得到 (0.560, 0.470, 0.515)，各通道绝对误差不超过 `1e-4`。红通道输入 0.95 时，裁切前应为 1.055，并计为越界。合成用例直接在线性浮点域运行。
2. **坐标、留出与空结果。** 把同一批合成色块移动到图中其他位置并提供正确多边形，结果应相同。用一块均匀灰色、同一物理块的多个副本分别测试，均应记录参照不足。两种合格亮度且无留出时，应有图、无独立色差。改变留出块的目标值时，冻结角色后拟合系数应不变。恒等映射的 256 个灰阶经过 sRGB 往返编码应逐级一致。
3. **真实运行对账。** 所有预定 ID 均有且仅有一行。参考数、两类成功数、不可用数和输入异常数闭合。随机性若非必要一律不用。相同冻结输入、相同环境的两次运行，按 ID 排序后比较状态、系数、色差、裁切计数和 PNG 解码像素哈希，排除时间戳与目录前缀。遇到缺数据的组合继续完成其他组合。出现数值或回放不一致先定位并修复实现，任何协议变更留给单独版本。
4. **报告证据边界。** 标明哪些是真实图像结果、哪些只是合成验算。单一固定物或人工辅助的成功，只能支持相应条件下的可行性。若预定图像普遍只有单一底色，给出原图证据、受影响帧数和每通道跨度，这同样完成了对本方法适用性的测试。

**已完成的合成验算。** 独立使用 scikit-learn 1.8.0 验证第 1 项，三个预测通道相对预期的最大绝对误差为 2.62 × 10⁻⁹ 以内。色块平移后得到相同系数，固定拟合块后改变留出块目标值也得到相同系数，256 个灰阶恒等往返逐级一致。这些结果只核对数值方向与实现约定。本地 Codex 须对实际接入的 v1.1 数值内核复核，牙齿图像的效果以真实运行结果为准。

**方法依据。** 牙科摄影已有离体牙实验以标准灰卡校正白平衡及曝光。夹具能否充当本项目的相对颜色参照，由第 5 节的独立留出检验决定。[Hein 与 Zangl，2016](https://pubmed.ncbi.nlm.nih.gov/27092350/)

线性 sRGB 的编解码及 Huber 参数可分别查阅规范与实现文档，运行版本以冻结配置为准。[W3C sRGB](https://www.w3.org/TR/css-color-4/#predefined-sRGB) · [HuberRegressor](https://scikit-learn.org/stable/modules/generated/sklearn.linear_model.HuberRegressor.html)
